# AI Management

This project uses GitHub Copilot as the primary AI coding assistant. AI agents do not automatically know how this codebase is structured, what conventions we follow, or what components already exist. Instruction files tell them.

This page explains how that system works so anyone on the team can use it, maintain it, and add to it.

---

## How It Works

When GitHub Copilot opens a chat session, it automatically loads `.github/copilot-instructions.md` from the repository root. That file uses `@` references to pull in other documents as context. Every agent — regardless of which AI model is active — reads those documents before responding.

```
.github/copilot-instructions.md   ← loaded automatically by Copilot (all models)
CLAUDE.md                          ← loaded by Claude Code CLI + Copilot on Claude model
  │
  ├── @AGENTS.md                       ← the agent team, their roles, and the component pipeline
  └── @docs/guidelines/essentials.md   ← the small always-on core: styling/typography rules,
                                          a11y floor, stack versions, high-frequency gotchas,
                                          and pointers to the on-demand reference below
```

The heavy reference docs are **not** eagerly imported — that keeps the always-on context lean (measured by `npm run context-budget`). They load on demand when the task needs them:

- `docs/guidelines/typography.md` — full type scale and composition
- `docs/guidelines/component-selection.md` — when-to-use judgment + the rule to use existing components
- `codemap.json` / `CODEMAP.md` — the **generated** component inventory (names, paths, status, composition, where-used)
- `.github/instructions/a11y.instructions.md` — full WCAG 2.2 AA catalogue (auto-applied to UI files in Copilot)

The result: every session starts lean — core rules + team structure — and pulls the bulky reference only when relevant.

## When to Create a New Guideline

If the same problem keeps recurring in AI output, that's a signal. A new guideline file is the fix.

Common triggers:

- An agent repeatedly uses a pattern you've corrected more than twice
- A new area of the codebase has rules that aren't obvious from the code itself
- A convention exists in the team's heads but nowhere in writing
- A component, token, or API is consistently misused

**Process:**

1. Write the guideline in `docs/guidelines/` as a focused `.md` file
2. If it's a small, always-relevant rule, fold it into `docs/guidelines/essentials.md`. If it's bulky reference, add a **pointer** to it from `essentials.md` ("read X before doing Y") rather than an eager `@import`
3. Keep it short — the always-on core loads every session; the `context-budget` guard watches its size

---

## Adding a Reference

Keep the always-on context lean. For a small, always-relevant rule, add it to `docs/guidelines/essentials.md` (imported by both entry points — one shared source). For bulky reference, create a focused `.md` and add a **pointer** to it from `essentials.md` rather than an eager `@import` — eager imports load every session and are what the context-budget guard watches.

The two entry points import only the core:

```
@AGENTS.md
@docs/guidelines/essentials.md
```

Files are: `.github/copilot-instructions.md` and `CLAUDE.md` in the repository root. After changing the always-on set, run `npm run context-budget` to confirm it stays lean.

## Writing Effective Guideline Files

<table>
  <thead>
    <tr>
      <th>Do</th>
      <th>Don't</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>State the rule first, explain second</td>
      <td>Bury the constraint in paragraph four</td>
    </tr>
    <tr>
      <td>Use tables for reference data (prop names, token names, etc.)</td>
      <td>Write long prose when a list is clearer</td>
    </tr>
    <tr>
      <td>Use strong language for hard rules: <strong>always</strong>, <strong>never</strong>, <strong>must</strong></td>

    </tr>
    <tr>
      <td>Include a concrete example of the wrong pattern and the right one</td>
      <td>Assume the AI will infer what you mean</td>
    </tr>
    <tr>
      <td>Keep each file focused on one area</td>
      <td>Combine unrelated rules into one large file</td>
    </tr>

</table>

## Model Switching

The instruction system is model-agnostic. Switching between Claude, GPT-4o, Codex, or Gemini in GitHub Copilot does not require any changes — `.github/copilot-instructions.md` is loaded regardless.

`CLAUDE.md` additionally serves the Claude Code CLI (Anthropic's terminal tool). Keep both files identical to avoid divergence.

---

## For New Team Members

You do not need to understand this system to use Copilot day-to-day. The files load silently in the background.

You do need to understand it if you are:

- **Getting unexpected output from an AI agent** — check whether a guideline file covers the area. If not, consider writing one.
- **Building a new component** — check the code map (`codemap.json` / `CODEMAP.md`) for what exists, and `docs/guidelines/component-selection.md` for the rule to use an existing component first. AI agents are instructed to follow this; so should you.
- **Adding a new convention to the codebase** — write it down in `docs/guidelines/` so AI agents learn it too.

The goal is a shared understanding between the human team and the AI tools. When the guidelines are current, AI output requires less correction. When they fall behind, expect drift.
