# Features

Features are complete, self-contained user journeys — the kind of thing a member does from start to finish in a single sitting.

---

## What's the difference between a Feature and a Component?

A **component** is a building block. A Button, an Alert, a form field. It does one visual job and knows nothing about your application or your data.

A **feature** is a full experience. It combines multiple components, manages its own steps, and handles a real member task — things like checking eligibility, changing an investment mix, or completing a multi-step form. Features know about your data, your flow, and your domain rules.

Think of it this way:

| | Component | Feature |
|---|---|---|
| **Example** | Button, DatePicker, Alert | Investment Mix Flow, Eligibility Checker |
| **Does one thing** | Yes | No — it owns a whole journey |
| **Manages steps or state** | No | Yes |
| **Knows about member data** | No | Yes |
| **Can be dropped anywhere** | Yes | Designed for a specific context |

---

## When do you use a Feature?

Reach for a feature when you need to drop an entire end-to-end flow into a page — not just a visual element. Features take care of the journey so the page only needs to host them.

If you just need to show or collect a piece of information, you want a component. If you need to walk a member through something with multiple steps or decisions, you want a feature.
