# Semantic Tokens Overview

Which token to reach for and why. All live swatches are in [Colors](?path=/docs/design-tokens-colors--docs).

## Token groups

| Group | What it covers | Example use |
|---|---|---|
| **Brand** | Identity colours — primary, secondary, and optional tertiary/quaternary | Buttons, active states, links, key UI moments |
| **Interaction Surfaces** | Tinted fills for interactive states | Soft buttons, ghost hovers, selected cards |
| **Status** | Feedback colours — error, warning, info, success | Alerts, validation messages, status indicators |
| **Surface** | Page, card, and modal backgrounds | Layout hierarchy |
| **Text** | Semantic text roles | Body, headings, muted labels, links |
| **Border** | Dividers, outlines, focus rings | Separators, form fields, keyboard focus |
| **Action** | Hover, selected, focus, and disabled overlays | Interaction states on neutral surfaces |

---

## Brand colours

Each brand colour (`primary`, `secondary`, `tertiary`, `quaternary`) has these fields:

| Field | When to use |
|---|---|
| `.main` | The identity colour itself — buttons, active icons, indicators, links |
| `.light` | A lighter variant — in dark mode, used as the text colour on hover and active interactive fills for improved contrast |
| `.dark` | A darker variant — in light mode, used as the text colour on hover and active interactive fills for improved contrast |
| `.contrastText` | Text placed directly on a `.main`-coloured surface |
| `.softLight` | The subtlest tinted fill — outlined button hover |
| `.softMain` | The base tinted fill — soft button resting state, selected inputs and cards |
| `.softDark` | Deepened fill — soft button hover, ghost button pressed |
| `.softDeeper` | Deepest fill — soft button pressed |

The `soft*` tokens are the **interaction surfaces** — see the section below.

Status colours (`error`, `warning`, `info`, `success`) additionally carry `.background`, `.text`, and `.border` for alert and status surfaces. These don't exist on brand colours.

---

## Interaction surfaces

Four intensity levels for brand-coloured tinted fills, used across buttons, tabs, and selectable inputs:

| Token | Intensity | Used for |
|---|---|---|
| `.softLight` | Lightest | Outlined button — hover |
| `.softMain` | Base | Soft button resting · ghost button hover · outlined button active · selected card/input |
| `.softDark` | Medium | Soft button hover · ghost button active |
| `.softDeeper` | Deepest | Soft button pressed |

All four levels are darker in dark mode to maintain the same perceived fill weight.

## ART vs QSuper — where values differ

Token *names* are the same across both brands. These values differ:

**Light mode**

| Token | ART | QSuper |
|---|---|---|
| `text.primary` | #333333 | Slightly lighter neutral |
| `text.linkInverse` | Light blue | White — QSuper's primary is lower-contrast so needs full white on dark backgrounds |
| `background.tintCool` | Sky blue | QSuper sky blue |
| `background.tintNeutralCool` | Clear blue | QSuper sky blue (lighter) |
| `background.tintWarm` | Salmon | Neutral grey — QSuper has no warm brand tint |

**Dark mode**

| Token | ART | QSuper |
|---|---|---|
| `text.primary` | #dadada | Brighter white — compensates for QSuper's lower-contrast primary |
| `text.muted` | Slightly lighter | Neutral grey |
| `divider` | Subtle dark | Neutral dark |
| `border.default` | Subtle dark | Neutral dark |
| `border.input` | Mid-grey | QSuper neutral |
| `background.tint*` | All unify to dark charcoal | All unify to dark neutral |

---

## Don't introduce new colours

If none of the existing tokens fit a design decision, don't reach for a raw hex value. Raise it with Moe — it either belongs as a new token in the system (available to every brand and mode) or an existing token covers the case and just needs to be applied differently.
